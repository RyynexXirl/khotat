# AGENTS.md

## Project overview

حلقة حمزة بن عبدالمطلب is an Arabic-only, RTL, mobile-first app for managing a Quran memorization circle. Four roles share one app: الشيخ (admin), مشرف (teacher of one group; stored as `supervisors` in the DB), محفظ (teacher of individually assigned students; stored as `muhaffizeen`), and طالب (student). Data is stored in Netlify Database (Postgres) via Drizzle ORM.

## Conventions

- All UI copy is Arabic and goes through `usePrefs().t` (`src/lib/i18n.tsx`); `<html lang="ar" dir="rtl">`. Use logical Tailwind utilities (`ps-`, `pe-`, `start-`, `end-`, `text-start`).
- Design: the original emerald/gold Islamic look (patterned `pattern-stars` header bands, rounded cards). Theme colors live in `src/styles.css` (`:root` and `.dark`). Fonts: IBM Plex Sans Arabic (body), Amiri (`font-display`). Add `dark:` variants for any hard-coded Tailwind colors.
- Statuses: `pending | done | missed | debt` (no partial/excused). Debts count = `debt` + `missed` (`DEBT_STATUSES`).
- Progression is strictly ordered: only the current lesson (first not done) can be marked done, and it may be ahead of its date; only the last done lesson can be undone; "missed" only once the lesson's date has come. Enforced server-side in `gradeOne`. Days with no text are skipped. Grades are toggleable: re-clicking «تم الحفظ» on the last done lesson or «لم يحفظ» on a missed current lesson returns the day to `pending`.
- Dates are stored as `date` strings (`YYYY-MM-DD`) and "today" is computed in Asia/Riyadh.
- Files imported by Netlify Functions use relative imports with `.js` extensions (no `@/` alias).
- PDF export is print-based: the plan page swaps to `PlanPrint` (landscape `@page`, Sun–Wed weekly table with من/إلى/السورة columns parsed from the plan texts) and calls `window.print()` — the browser's "Save as PDF" produces the file. Table styles live at the bottom of `src/styles.css` (`.print-root`).
- The Sheikh's destructive actions (delete, rename, change group, assign muhaffiz, delete accounts) are hidden behind a "وضع التعديل" (Edit Mode) switch on `/sheikh`.

## Non-obvious decisions

- Authentication is a prototype: the Sheikh enters a password (default `1234`, persisted in `settings.sheikh_password` once changed); supervisors/muhaffizeen log in by picking their name from a dropdown + their password (set by the Sheikh when he creates the account); students self-register (name auto-formatted to «X بن Y Z», group, sub-group for الأجاويد, phone, password) and log in by picking group → name → their password. Passwords are stored in plain text and the server functions do not authorize per role. Add real auth (e.g. Netlify Identity) and per-function checks before production.
- Plans are written by hand by the مشرف/محفظ or Sheikh. New students (registered or added by the Sheikh) get empty rows for every lesson day. The `muhaffiz_and_auth` migration wiped the old demo students/supervisors — only the groups and the Sheikh login remain.
- If the demo data needs to change, add a new migration. Don't modify the seed migration once it has been applied.
